What changed with ADR 0033 is where the line falls: the free half is product code and runs on every press.

src/ainews/quality/ is imported by the pipeline on purpose: it reads rows, calls no model and writes nothing, and persist stores what it returns on the bulletin. src/ainews/evals/ reads the database, quality/ and the pipeline's node functions, and is imported by cli.py alone — never the pipeline, never the web layer. The arrow points one way, and that is the whole rule.

1 · CHECKS

free · at every press · $0

quality/checks.py — rows in, numbers out

persist → bulletins.checks_json → /runs/<id>

word_budget → ≤5% of summaries over 55 words; 0 over on why_it_matters and the title

ungrounded_numerals → a figure in the summary the body never carried

content_floor → did the summariser name the key fact, did it survive into the writing, did the body's numerals reach the summary at all

tag_vocabulary → singleton share ≤70% · importance_distribution · tier_shape

ranker_vs_fallback → reported, never asserted: an overlap equal to the ceiling means the rank call bought nothing

unrepresented_fives · editor_note_shape → 3 paragraphs of 25–40 words

Computed once, at the press.

Stored on the bulletin rather than recomputed when the page is drawn: a page that re-scores an old day with today's checks reports one experiment under another one's heading.

The same pure functions run over a recorded fixture inside pytest, which is what lets a bound be asserted offline, with no key and no network.

Why a content check at all: a regression to three generic, numberless sentences passes every shape check here, and passes the grounding judge too — it asserted nothing.

2 · THE READER

free · inside the app

the only ground truth there is

POST /verdict · _story_foot.html

Every story carries Doğru · Yanlış, drawn at rest. One Verdict row per summary; a later verdict overwrites the earlier one.

A Yanlış opens four words, because a story block asserts four separate things:

wrong_fact   not_news   duplicate   wrong_place

Only wrong_fact calibrates the judge. The other three leave the 2×2 entirely and are counted on their own — they measure the relevance call, the dedupe and the ranker.

Binary, and named.

A person reading a digest can say "that is wrong" in one click and cannot honestly say "that is a 3", so there is no five-point scale. What was missing was never resolution — it was which claim.

The hover reveal is gone. Three days of it collected five labels over 138 summaries, and on a touch screen it never fired at all.

A "wrong" with no reason — every label from before the field existed — is set aside rather than assigned one on the reader's behalf.

3 · JUDGE

spends money on purpose

gpt-5.6-terra — a tier above the pipeline

ainews eval judge --run <id> --sample 12 --seed 0 --max-cost 0.10

1 · sample twelve summaries, seeded, from the published stories first — the reader labels what the page showed, so a uniform sample over ninety lands nowhere near a label

2 · estimate the spend from prompt length before the first call; CostGuard raises above --max-cost and nothing is sent

3 · one binary question: is every factual claim in summary + why_it_matters supported by the body?

4 · one EvalResult row per summary, keyed on the bulletin, carrying the prompt's hash

One question, and nothing else.

Not style, not length, not importance, not language: Turkish quality is judged by the reader, never by a model. A verdict that fails to parse is recorded as passed = None, not raised.

TPR and TNR separately, never one accuracy figure — the classes are unbalanced and a single number hides the only failure worth catching. Beside them, precision: of the summaries the judge failed, the share the reader agreed were wrong.

Twelve a run is about $0.02, roughly $2 a month at one judged run a day, against the product's own $2.50.

4 · RANK STABILITY

≈ $0.006 · two extra rank calls

and the same number ships on every bulletin

ainews eval rank-stability --run <id> --times 3

The candidate table's order is an accident of the database. Shuffle it three ways under seed + i, rank each, then compare what comes back.

score = min( mean Kendall τ , chance-corrected Jaccard )

τ returns 0.0 below two shared items, not 1.0 — three pairwise-disjoint top-5 orders must not pass a gate hardest exactly where they share least.

A run that fell back to importance order records passed = None: a score over a deterministic fallback measures nothing.

Both halves, or neither means anything.

Three readings can pick the same fifteen in three unrelated orders, or order five identically while disagreeing about which five belong.

Why corrected, not subtracted. Fifteen picks out of twenty-seven candidates overlap 0.385 by coin flip. Subtracting that caps a perfect ranker at 0.615, and a 0.6 gate would then be measuring the size of the pool. Dividing by the room above chance runs 0 at indifference to 1 at agreement.

Production stores the same number on bulletins.agreement, so the probe is a check on a figure the page already reports rather than the only reading of it.

shuffle A -> [8, 3, 5, 1]
shuffle B -> [3, 8, 1, 5]
concordant 4 · discordant 2 -> τ = 0.33

E = k / (2N - k) = 15 / (54 - 15) = 0.385
J = 0.62  ->  (0.62 - 0.385) / 0.615 = 0.38
score = min(0.33, 0.38) = 0.33

measured: τ 0.47 and 0.50, both before the
page read the ranker's order and before the
correction. the next press is the first
reading that counts.

5 · PROMPT COMPARISON

≈ $0.02 a comparison

refused above --max-cost before the first call

ainews eval corpus --size 40
ainews eval compare --prompt-a a.md --prompt-b b.md

corpus freezes article bodies out of the archive into a gitignored JSONL file, chosen by a seeded hash of the id — same seed, same corpus, so two comparisons a week apart are about the prompt and not about the week.

compare summarises every one of them twice and prints the checks side by side. Same bodies, same model, same seed.

It names no winner.

The numbers are shape and content floors, not a preference: a prompt that writes shorter summaries scores better on the word budget and may say less. What the command removes is the need to buy a production run to find out what a wording did.

The corpus is gitignored for the reason the fixtures carry no bodies: the repository is public and an article is someone else's text.

6 · REPORT

free

ainews eval report [--run <id>]

Prints every number above and appends one dated section to docs/evals.md — appended, never edited: a section is what was measured on that date.

It prefers the checks the press stored on the bulletin and recomputes only where a bulletin predates them, and it says on the page which of the two it drew.

Each row names the function that produced it. A block byte-identical to one already in the file is written as a line pointing back, so the record grows by the run count and not by the report count.

A response is triggered by a measurement, not by a schedule

score < 0.6 across runs → the three shuffled rank calls are already in production; the next lever is the candidate table, not the aggregation

ranker / fallback overlap = the ceiling on most runs → the rank call is buying nothing; delete it

judge TPR or TNR < 0.8 after thirty labels a class → rewrite the judge prompt from the wrong notes, and compare the two over the frozen corpus before it ships

key fact named but not kept, run after run → the fault is the writing instruction, not the model tier

golden duplicate pairs keep failing on new outlets → embedding dedupe, and its own ADR

docs/EVALUATING.md is the manual: what each number means, when it is worth believing, and how to add a check.
